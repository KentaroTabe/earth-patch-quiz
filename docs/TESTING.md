# 五人に触ってもらう

仕様 §1 と §13（M1）のための手順書。**計測コードは入っていない**ので、見て記録する。

---

## 1. 確かめたいこと（一つだけ）

> **予備知識のない人が、3問続けて大きく外しても4問目をめくるか**

これ一点。地理に明るい人が楽しめるのは分かりきっているので、検証する意味がない。**知らない人が「分からなかったけど面白かった」と思えるかどうか**だけを見る。

判断の目安（仕様 §1）。

| 見るもの | 目安 |
| --- | --- |
| 1セッションの中央値の到達問数 | 7問以上（1セット10問） |
| 大きく外した直後に次へ進んだ割合 | 高いほどよい |
| 「解説」を最後まで読んだ割合 | 50%以上（低いなら解説は要らない） |

### 「外した」の線引き

仕様は定義していないので、ここで決める。

| 呼び方 | 距離 | 得点 | 根拠 |
| --- | --- | --- | --- |
| 外した | 1,000 km 以上 | 2,567点以下 | 終了画面の「外した場所の一覧」に載る線と同じ |
| **大きく外した** | **3,000 km 以上** | **677点以下** | だいたい大陸が違う。主指標はこちら |

## 2. 確かめないこと

やると結論が濁るので、この五回では見ない。

- 見た目の好み（配色、字の大きさ）
- 問題の難易度が適切か（バンクが25問しかないので、まだ測る意味がない）
- 得点の式が妥当か
- 弁別性の重み（別作業。docs/SCORING.md §3）

「面白いか」も直接は聞かない。理由は §6。

---

## 3. 誰に触ってもらうか

**予備知識のない人を五人。** ここを外すと、この検証は丸ごと無駄になる。

事前に、目的を伏せたまま雑談で確かめる。

- 旅行や地理が趣味か
- 世界地図を見る機会があるか
- 国旗や首都の暗記が得意だったか

**すべて「いいえ」に近い人を選ぶ。** 地理好きの反応は聞かなくても分かっている。

**目的は事前に言わない。** 「3問外しても続けるか見たい」と伝えた瞬間、続けてしまう。

---

## 4. 一回のセッションの流れ（20〜25分）

### 導入（1分）

言うのはこれだけ。

> 「衛星画像を見て、どこだと思うか地図をタップしてください。
> **途中でやめて構いません。やめたところが、いちばん知りたいことです。**」

**やめてよいと最初に一度だけ言う。** そのあとは二度と言わない。これを言わないと、全員が義理で10問めくってしまい、到達問数が測れなくなる（§8）。

操作の説明はしない。分からなければ、それ自体が結果。

### 観察（10〜15分）

**黙って見る。** 助けない。答えを言わない。設計の意図を説明しない。

**横に座らない。** 画面が見える斜め後ろか、画面共有で自分のカメラを切る。目が合うと人はやめられなくなる。

記録するのは §5 の表。

### 事後（5分）

§6 の質問。

## 5. 記録シート

### 問ごと

| 問 | 場所 | ピンまで（秒） | 外れ（km） | 「次へ」まで（秒） | 解説 | ヒント | 声・手の動き |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | | | | | 読／流／無 | 有／無 | |
| 2 | | | | | 読／流／無 | 有／無 | |
| … | | | | | | | |

- **場所・外れ（km）** … 結果画面に出ているものをそのまま写す
- **解説** … 広域画像・地図・本文のどれを見ていたかも書き添える
- **「次へ」まで** … 結果画面が出てから「次へ」を押すまで。**これが主指標**（§8）
- **解説** … 読＝最後まで目で追った／流＝途中で視線が外れた／無＝読まずに押した
- **声・手の動き** … 「うわ」「全然ちがう」「あー」。笑ったか、身を引いたか

| --- | --- |

## 6. 聞くこと・聞かないこと

### 聞かない

- **「面白かったですか？」** … 対面では必ず「面白かった」と返ってくる。情報がない
- 「どこを直すといいですか？」 … 相手は設計者ではない
- 「また使いますか？」 … 「はい」しか返ってこない

### 聞く

行動を聞く。感想は聞かない。

- 「**どこでやめたくなりましたか。**」
- 「分からなかったとき、どう思いましたか。」
- 「解説は読みましたか。**どれか覚えていますか。**」← 覚えていれば読んでいる
- 「**次にこれを開くとしたら、いつ、どこで開きますか。**」← 具体が出るか
- 「**誰かに見せるとしたら、誰ですか。**」← 名前が出るか

最後の二つが、いちばん嘘の混じりにくい問い。

### 一週間後

URL を渡して何も言わず、**自分から開いたかどうか**を後で聞く。言葉より強い。

## 7. 五人ぶんが揃ったら

判定は三つ。

1. **主指標** … 3問続けて大きく外した人のうち、4問目に進んだ人の数
2. 到達問数の中央値（五人なら3人目の値）
3. 解説を最後まで読んだ問の割合

### 進めてよい形

主指標がほぼ全員「進んだ」で、到達問数の中央値が7問以上。→ 仕様 §13 の M2（取得パイプライン、100問）へ。

### 止まる形

3問外したところで半数が離脱。→ **問題数を増やしても直らない。** 何を変えるかを決めてから先へ進む。仕様 §13 が言うとおり、パイプラインは面白さを作らない。

### 解説が読まれていない形

読了が半数を切ったら、**仕様 §1 の但し書きどおり「解説は要らない」という判断がありうる。** 書くのに1問10〜15分かかっている工程なので、ここは正直に見る。

## 8. この方法の弱いところ

先に書いておく。読まずに数字だけ見ると間違える。

### 一番弱いのは到達問数

**見られている人はやめられない。** 作った本人が横にいる場で、4問目で「もうやめます」と言える人はほとんどいない。つまり到達問数は上振れする。中央値7問を超えても、それだけでは何も証明できない。

だから **「次へ」までの秒数** のほうを主に見る。義理で続けている人は、結果画面をほとんど読まずに押す。楽しんでいる人は、地図を見比べてから押す。この差は取り繕えない。

対策は三つ。

- やめてよいと最初に一度だけ言う
- 横に座らない、目を合わせない
- 画面共有ならカメラを切る

### 五人では中央値が動く

五人の中央値は3人目の値。**一人違うだけで結論が変わる。** 数字は参考にとどめ、観察のほうを重く見る。

### 端末を使い回すと問題が変わる

進捗は `localStorage`（キー `earth-patch/v1`）に入り、**直近に出した問題は次のセットから外れる**（仕様 §7.3）。同じ端末を五人で回すと、二人目から別の問題になる。

**毎回シークレットウィンドウを開く**か、セッションのたびに `localStorage` を消す。

なお、記憶を消しても **出題される10問は毎回ランダム**（難易度の配分だけは 1,1,2,2,2,3,3,4,4,5 で揃う）。五人に同じ問題を出したい場合は、そのための仕掛けが要る（未実装）。

## 9. ついでに決まること

このセッションで、仕様 付録の未確定事項が二つ片づく。

**#5 国名ラベルの初期値。** いまは表示あり。地図の右上で切り替えられる。**五人のうち二人には最初から切っておいて**、ピンの置き方が変わるかを見る。ラベルが無いと地図が模様にしか見えない人がいるかどうかが分かる。

**#4 1セットの問数。** いまは10問。到達問数がどこで頭打ちになるかを見て決める。全員が10問めくり切るなら増やす余地があり、5〜6問で落ちるなら減らす。

```bash
npm run check                    # データの規約違反がないこと
npm run fetch -- --verify-only   # 画像25枚が公開URLから読めること
```
