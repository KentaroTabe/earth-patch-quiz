# ここはどこ ── EARTH PATCH

衛星画像から場所を当てるクイズ。世界地図にピンを打って答える。

- 版: 0.1（プロトタイプ / 仕様書の M2 相当）
- 収録: 100問（1セット10問）
- 画像: Cloudflare R2 から配信（200枚・56MB）
- 仕様書: [earth-patch-spec.md](earth-patch-spec.md)

### 何が入っているか

| 分野 | 問数 | | 分野 | 問数 |
| --- | --- | --- | --- | --- |
| 火山・カルデラ | 16 | | 山地・峡谷 | 9 |
| 湖・内陸水 | 13 | | 河川・デルタ | 9 |
| 砂漠・砂丘 | 12 | | 広大で特徴が少ない | 9 |
| 都市・人工物 | 12 | | 農地・灌漑 | 6 |
| 海岸・島・半島 | 10 | | 氷河・寒冷地 | 4 |

枠は 200 km²（一辺14km）から 180000 km²（一辺424km）まで。難易度は 1:17 / 2:26 / 3:32 / 4:16 / 5:9 で、1セット `1,1,2,2,2,3,3,4,4,5` を10セット分まかなえます。

**砂漠・山地・フィヨルドは一段階大きい枠を使っています。** 砂丘の列も褶曲の縞も峡湾の刻みも、狭い枠では模様の一部しか入らないためです（[docs/IMAGERY.md](docs/IMAGERY.md) §2）。

## 動かす

依存パッケージはゼロ。ビルド工程も無い。

```bash
npm run serve
```

`http://localhost:4173/` を開く。`index.html` をダブルクリックしても動く（データは `fetch` ではなくグローバル変数で読んでいるため）。

問題画像は R2 から読むので、クローンしただけで動く。手元に画像を落としたいときは `npm run fetch`（`img/q/` は Git に入れていない）。

## 何を確かめたいのか

**「予備知識のない人が、3問続けて大きく外しても4問目をめくるか」** ── これ一点。

地理に明るい人が楽しめるのは分かりきっているので、検証する意味がない。知らない人が「分からなかったけど面白かった」と思えるかどうかだけを見る。

だから **ランキングも対戦もタイムアタックも入れていない**（仕様 原則7）。競技性を入れると、外した人が離脱する方向に力がかかる。確かめたいのは逆のこと。

計測コードは入っていない。まず対面か画面共有で五人に触ってもらう。**手順と記録シートは [docs/TESTING.md](docs/TESTING.md)。**

```
.
├── index.html                 画面の骨組み
├── assets/
│   ├── config.js              サイト側の設定（画像の置き場所もここ）
│   ├── style.css              配色・組版
│   ├── app.js                 出題・採点・進行
│   └── map.js                 投影・描画・point-in-polygon
├── config/
│   ├── pipeline.json          取得と採点のパラメータ
│   └── sources.json           画像の取得元
├── data/
│   ├── questions.js           問題データ（人が書く）
│   └── world.js               陸地・国境ポリゴン（自動生成 223KB）
├── img/
│   ├── manifest.js            画像の一覧（自動生成）
│   ├── q/*.jpg                出題する枠 100枚（Git には入れない。npm run fetch で作る）
│   └── ctx/*.jpg              結果画面に出す広域 100枚（同上）
├── scripts/                   取得・採点・検査（Node.js。公開時には動かない）
├── docs/
│   ├── TESTING.md             五人に触ってもらう手順
│   ├── SCORING.md             弁別性と知名度の詳細
│   ├── IMAGERY.md             取得・R2・差し替えの手順
│   └── DATA_SCHEMA.md         データの書き方
└── .env.local.example         R2 の認証情報の雛形（.env.local はコミットしない）
```

### コマンド

```bash
npm run scan        # Wikidata から候補点を作る
npm run score       # 弁別性を計算し、難易度を決める（-- --write で書き戻す）
npm run fame        # 手で選んだ問題の言語版数を測る
npm run fetch       # 画像を取得して R2 へ上げる（1問につき出題用と広域の2枚）
npm run fetch:dry   # 通信せず、叩く URL だけ確認する
npm run sheet       # 目視用の一覧を書き出す
npm run world       # Natural Earth から world.js を作る
npm run validate    # データの規約違反を検査する
npm run check       # 構文チェック + validate（Pages のビルドコマンド）
npm run serve       # ローカル配信
```

## デプロイ（Cloudflare Pages）

Git 連携で push すれば自動デプロイされる。

```
Build command:      npm run check
Build output dir:   .
```

`npm run check` が落ちると公開されない。データの規約違反はここで止まる（仕様 §10）。

### 画像（R2）

25枚とも Cloudflare R2 のバケット `earth-patch-quiz` にあり、サイトはそこから読む。`img/q/` は Git に入れていない（仕様 §4.1）。

認証情報は `.env.local`（`.gitignore` 済み）から読むので、リポジトリには入らない。

```bash
cp .env.local.example .env.local   # 値を入れる
npm run fetch -- --upload-only     # 手元の画像を R2 へ上げ、公開URLから読めるか確かめる
npm run fetch -- --verify-only     # 公開URLから読めるかだけ確かめる
```

**アップロードのあとは必ず公開URLからの読み取りを確認する。** バケットへの書き込みが成功していても、公開設定が入っていなければサイトからは見えない。`npm run fetch` はこれを自動で確かめ、読めなければ終了コードを 1 にする。

**いまの公開URLは `r2.dev` の公開エンドポイント。** 仕様 §4.2 は本番で使わないよう明示している。レート制限を超えると 429 が返るため、五人に触ってもらう段階を越えるならカスタムドメインへ移すこと。手順は [docs/IMAGERY.md](docs/IMAGERY.md) §5。

## 仕様書からの差分

仕様に書かれていない判断をしたところ。理由も併記する。

| 箇所 | 仕様 | 実装 | 理由 |
| --- | --- | --- | --- |
| 枠の上限 | 2000 km²（§5.4） | 180000 km² まで伸ばした | 内陸デルタ・三角州は一辺45kmの枠に収まらなかった。さらに砂漠・山地・フィヨルドは、模様が広い範囲で初めて読めるので一段階大きい枠にしてある |
| 結果画面の広域画像 | 記載なし | 一辺3倍の画像に、出題した枠を白い四角で重ねる | テストで「正解発表のときに一回り大きい画像があると納得感が出る」という声が出た |
| 画面の分割 | 縦一列（§7.1） | 900px 以上で左に画像、右に地図と解説 | 縦に積むとパソコンでは画面が余り、画像と地図を行き来するのにスクロールが要る。スマホは縦一列のまま |
| 無雲モザイク | 未確定（付録 #1） | NASA GIBS の Landsat 年次モザイク（30m） | 認証なしで一次配布元から取れる唯一の全球無雲モザイク。ライセンスが明快 |
| R2 の設定 | 記載なし | アカウントID・バケット名・鍵を `.env.local` から読む | 公開リポジトリなので、設定ファイルに書かずに済ませる |
| アップロード後の確認 | 記載なし | 公開URLから読めるかを1件ずつ確かめ、駄目なら終了コード 1 | 書き込みが成功していても公開設定が入っていなければサイトからは見えない。実際にこれで詰まった |
| 設定ファイル | 記載なし | `config/pipeline.json` / `config/sources.json` / `assets/config.js` | 閾値・重み・枠サイズをコードに直接書かないため |
| 水域率の判定 | NDWI（§5.3） | 取得元によって NDWI と RGB の経験則を切り替え | GIBS の合成画像は表示用に伸張されており、NDWI だと砂漠が水域94%になった。詳細は docs/SCORING.md §2 |
| 知名度の正規化 | `norm(log(1+言語版数))`（§5.5） | `norm()` を候補集合内の分位正規化として実装 | §5.3 の `norm()` と同じ定義に揃えた。絶対値だと難易度1〜2に固まる |
| 沿岸の国判定 | point-in-polygon（§8.3） | 陸から外れた点は 120km 以内の最寄り国にスナップ | Natural Earth 1:110m は海岸線が粗く、マンハッタンを指しても「海の上」になる |
| 帯の文言 | 4種類（§8.3） | 「海の上を指しました。」を追加 | 海洋上を指したときに「大陸が違いました」と出るのは説明になっていない |
| ズームの実装 | `transform: scale()`（§8.1） | canvas の座標変換で同じ scale + translate | CSS 変換だと線がぼける。式は同じ |
| 問題数 | 未確定（付録 #4） | 1セット10問、バンク100問 | 1セットの問数は仮のまま |
| `wikipedia` / `reject` / `category` 項目 | 記載なし | `data/questions.js` に追加 | 知名度の実測、不採用の理由、分野の偏りを見るため |
| 下見の判定 | 雲・欠測（§5.4） | 走査線状の欠測を検出する指標を追加 | 輝度では落ちない欠測が最も多い不採用理由だった。ただし拾えるのは重症だけ |
| `scan` のクエリ | §5.2 のまま | 天体の絞り込み（`wikibase:geoGlobe wd:Q2`）を追加 | `P625` は月や火星の地物にも付いており、火星のカルデラが混ざる |

## 分かっていること・分かっていないこと

**分かっていること**

- NASA GIBS の年次モザイクは **2000年前後**の画像。それ以降にできた地物は写らない（パーム・ジュメイラ、三峡ダムの湛水で確認）
- 乾燥地・海岸線・火山はよく写る。**雪氷・塩原は白飛びし、湿潤な熱帯は走査線状の欠測が出る**
- 132件を検討して32件を落とした。落とした理由は [docs/IMAGERY.md](docs/IMAGERY.md) §4。**17件が走査線状の欠測**で、これが最大の不採用理由。10m の取得元に移せば大半は拾い直せる見込み
- **氷河・寒冷地がいちばん揃わない**（4問）。雪と氷は白飛びして、峰と氷河の区別がつかなくなる
- **r2.dev のサブドメインはバケットごとに別々に割り当てられる。** 別バケットの URL を使うと、アップロードは成功しているのに 404 だけが返る（移行時に実際に踏んだ）
- 枠の上限を 2000 → 20000 km² に伸ばしたら、難易度の配分が `7/6/4/2/1` から `8/4/6/4/3` に広がった。難易度は候補集合に対する相対値なので、問題を足すと全体が動く

**まだ決めていないこと**

- **弁別性の重み。** 仕様 §5.3 が要求する「100枚の目視ラベル付け」をやっていない。現在の重みは暫定値で、実際に人が見た印象と順位がずれている（[docs/SCORING.md](docs/SCORING.md) §3）
- **Wikidata のクラス指定**（仕様 付録 #3）。`wdt:P31/wdt:P279*` は上位クラスをたどりすぎて、カルデラの指定でも南極の乾燥谷が返ってくる
- **国名ラベルの初期値**（仕様 付録 #5）。表示ありを仮としている。難易度への影響が大きいので実測が要る
- **1セットの問数**（仕様 付録 #4）。10問は仮
- **カスタムドメイン。** いまは `r2.dev` の公開エンドポイントを使っている（仕様 §4.2 は本番で使わないよう明示）
